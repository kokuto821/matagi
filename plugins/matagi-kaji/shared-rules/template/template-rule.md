# スキル・エージェント テンプレートルール

## テンプレートの置き場所

| 種類 | テンプレートパス |
|------|----------------|
| スキル | `plugins/matagi-kaji/template/skills/SKILL.md` |
| サブエージェント | `plugins/matagi-kaji/template/agents/AGENT.md` |

## スキルテンプレート

### フロントマター

最小構成 `name`・`description` のみ。他は必要時のみ追加。

```yaml
---
name: skill-name        # ディレクトリ名と一致させる（kebab-case）
description: >          # 最重要。自動起動トリガー。要点を先頭に書く
  ...
---
```

オプションフィールド:

| フィールド | 追加するとき |
|-----------|-------------|
| `when_to_use` | description 補完のトリガー条件あり |
| `allowed-tools` | 使用ツール明示制限したい |
| `disable-model-invocation: true` | 副作用ありタスク型で手動起動のみにしたい |
| `context: fork` | 別コンテキストで隔離実行したい |

### 本文

> **スキル本文構成の定義 = ここが唯一の出典。** テンプレート本体（`template/skills/SKILL.md`）はこれを体現、`create-skill` はこれを参照。各所で構成を文章で再記述しない。

- **500行未満**を目安に保つ（ロード後 セッション中ずっとコンテキストに残るため）
- 詳細リファレンスは別ファイルに分離
- 構成: 「概要」→「ルール」→「手順」→「出力」が基本

| ブロック | 内容 | 省略 |
|---------|------|------|
| 概要 | 何をするスキルか（1〜2行） | 不可 |
| ルール | 当スキルが従う規約・判断基準。本文に直書きせず `rules/` / `reference/` 参照（[[externalization-rule]]） | ルール無しスキルは省略可 |
| 手順 | 実行ステップ。mermaid `flowchart TD` で書く（§手順の記述形式） | 手順なし参照型は省略可（§適用除外） |
| 出力 | ユーザーへ返す形式 | 不可 |

### タスク型 vs 参照型

| 種類 | 判断基準 | ポイント |
|------|---------|---------|
| タスク型 | デプロイ・コミット等 副作用あり | `disable-model-invocation: true` で手動起動に |
| 参照型 | 規約・スタイルガイド等 知識提供 | インラインで知識として効かせる |

## サブエージェントテンプレート

### フロントマター

最小構成 `name`・`description` のみ。

```yaml
---
name: agent-name
description: 委譲条件を具体的に書く
---
```

オプションフィールド:

| フィールド | 追加するとき |
|-----------|-------------|
| `tools` | ツールを制限したい（**省略すると全ツールを継承**） |
| `model` | コスト最適化したい（探索系は `haiku`）。省略で `inherit` |
| `memory` | 会話越しで学習を蓄積させたい |

`tools` は**省略するとメイン会話の全ツールを継承**。読み取り専用レビュー役など安全性を担保したいエージェントには必ず指定。

### 本文（システムプロンプト）

本文 = そのままシステムプロンプト。構造化 → 指示追従性向上。

推奨構成:

```
あなたは〇〇の専門家です。   ← 役割（1行）

呼ばれたときの手順:          ← 何をするか（mermaid flowchart TD ＋ 各ステップの詳細）
1. ...

チェックリスト / 観点:       ← 何を見るか
- ...

出力フォーマット:             ← どう返すか
- ...
```

見出し（`##`）・「ラベル + コロン」の効果は同等。本文が長い → `##` に切替。手順の書き方: §手順の記述形式 に従う。

## 手順の記述形式（スキル・サブエージェント共通）

> **手順の記述形式の定義 = ここが唯一の出典。** テンプレート本体（`template/skills/SKILL.md`・`template/agents/AGENT.md`）はこれを体現。各所で記法を文章で再記述しない。

**手順（実行ステップ・分岐・ループ・停止条件を含む記述）は mermaid `flowchart TD` で書く。** 番号リストや散文だけで分岐を表さない。条件分岐が文章に埋もれ解釈がぶれるのを防ぎ、フロー可読性を上げるため。下記「書き方」表の記法、色分け固定定義、図直下の固定文は、該当するものすべて必須。

### 書き方

| 要素 | 記法 |
|------|------|
| 方向 | `flowchart TD` 固定。`LR`・`sequenceDiagram`・`stateDiagram` は使わない |
| 置き場所 | 手順に当たるセクション（見出し名不問。`## 手順`・`# 指示`・「呼ばれたときの手順」など）直下に mermaid ブロックを1つ置く。その下に固定文（後述）、続けて各ステップ詳細 |
| レーン | **各手順を1つの `subgraph`（スイムレーン）で囲む。** 区切り: `### N.` 見出しあり → 見出し単位、無し → 番号項目単位、散文の番号は付け替えない。ID `L<連番>`、タイトル `"<番号> <見出し>"`（見出し・項目の要旨から作成、「—」等の装飾記号は除く）。全処理・判定ノードはいずれかのレーンに属する |
| 宣言位置 | ノードは自レーン `subgraph` 内で宣言、レーン内エッジもそこに書く。レーン跨ぎエッジは全 `subgraph` の後にまとめて書く（mermaid ではノード所属が宣言位置で決まるため）。`classDef`・`class` 文はブロック末尾にまとめ、インデント4スペース |
| 開始・終了 | `START(["START"])` / `END(["END"])` に統一（ID・ラベルとも大文字。mermaid では小文字 `end` が予約語のため）。待機・他フェーズへの移動など流れをそこで止めるノードは終端形 `([...])` で書き、内容をラベルにする（ID は内容を表す英語名でよい。例: `Resume`・`Wait`）。終端ノードはレーンに入れず先頭で宣言 |
| 処理 | `S1a["入力を集める"]`。ID `S<手順番号><連番文字>`（`S1a`・`S1b`…。連番文字は散文の副番号 8a・8b 等と無関係）。ラベルは何をするか短い動詞句 |
| 分岐 | `S1b{"issue 化すべきか？"}`。判定ノードは「〜か？」の疑問形、出るエッジは `-->|YES|`・`-->|NO|` の2本 |
| 3択以上の分岐 | YES / NO 判定を連鎖。連鎖順 = 評価順。「上から順に評価し、最初に該当したものを使う」表はそのまま連鎖になる |
| ループ・差し戻し | 戻りエッジで表す。回数上限等の停止条件は「上限に達したか？」判定ノードにし、YES → 報告ノード（または終端ノード）、報告後は END か後続手順へ。ユーザー応答待ちの再提示ループには上限を置かない |
| 承認ゲート | 「承認されたか？」判定ノードにし、NO → 修正して再提示する前のノードへ戻す |
| 実行主体の色分け | `classDef user`（黄）: ユーザーに確認・承認・選択・判断を求めるノード（凡例では「確認・承認」と書く）。対象: 質問ノード、ユーザー回答で分岐する判定ノード、承認ゲート。提示だけのノードには付けない。`classDef delegate`（青）: 他スキル・エージェント起動を伴うノード。産出者への差し戻し適用・レビュー再実行を含む。両方に当たるノードは黄優先。該当ノードがある色は必ず付け、該当ノードが無い色は定義しない |
| ラベルの文字 | ラベルは `"..."` で囲む。バッククォート・`<` `>`・`#`・`;` は使わない。読点・括弧は半角スペースに置換。回数上限等の数値、ファイルパス、フラグ・引数付きコマンドは書かない（散文に書く。コマンド名・委譲先名は、何をするかを示すため書いてよい） |
| 常時制約 | 手順ではない常時の制約・禁止（「〜しない」「格上げしない」など）は図に載せず散文に残す。制約・条件付きステップ混在の項目は、ステップのみ図に載せ、見出しは中立語（「結果を返す」など）。制約のみの項目はレーンを作らない |

色分け固定定義（ライト・ダーク双方で読めるよう文字色を明示）:

```
classDef user fill:#fff3bf,stroke:#f08c00,color:#000
classDef delegate fill:#d0ebff,stroke:#1971c2,color:#000
```

図直下に次の固定文を1行置く: `遷移は図に従い、判定基準・詳細は下の本文に従う。`

色分けを付けた場合、その下に凡例の固定文を1行置く: `凡例: 黄 = ユーザーの確認・承認、青 = 他スキル・エージェントへの委譲`。使った色の項目のみ書く（黄だけ → `凡例: 黄 = ユーザーの確認・承認`、青だけ → `凡例: 青 = 他スキル・エージェントへの委譲`）。

テンプレート配置の手順記述形式ポインタ（HTML コメント）は、スキル・サブエージェント生成後に削除可。

### 役割分担（二重管理を避ける）

- フローチャート = **遷移**（どこへ進む・戻る・止まるか）の正。
- 散文 = 各ノードの**詳細**（何をもって YES とするかの判定基準・数値・コマンド・委譲先・出力）を書く。散文側に遷移を再掲しない。
- 判定ノードラベルは短い疑問形にとどめ、判定基準は散文に書く。
- 食い違い発見時は図を正とする。既存資産は段階導入のため散文に遷移記述が残存。散文からの遷移記述整理は別 issue で扱う。本ルールは新規作成・更新時の書き方を定める。

### 適用除外

手順に当たるセクション自体が無いスキル／サブエージェント（スタンス列挙・出力形式定義のみのもの）は、フローチャートを置かない。手順に当たるセクションあり → 直線的手順にも一律に置く。図の要否を作者裁量にせず、検査・レビューを単純にするため。

## スキルとエージェントの連携

- エージェント側 `skills:` フィールド記載 → 起動時に当該スキル全文がコンテキストへ注入
- スキル側 `context: fork`・`agent:` 記載 → タスクとして指定エージェントで隔離実行可能
