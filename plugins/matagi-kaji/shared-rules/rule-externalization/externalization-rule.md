# スキル・エージェントにおけるルール外部化の原則

## 原則

スキル（`skills/`）・サブエージェント（`agents/`）の作成・編集時、内部にルール・制約・判断基準を記述する場合、**`rules/` に移せるものは必ず `rules/` に切り出し、そこから参照する。**

スキル／エージェントファイル内でルールをインライン完結させない。

## 「rules/ に移す」の判断基準

以下に該当 → `rules/` に切り出す:

| 該当するもの | 例 |
|------------|-----|
| 他スキル・エージェントでも適用の可能性あり | 命名規則、ファイル配置 |
| 「常に従うべき不変ガイドライン」の性質 | 禁止事項、必須フォーマット |
| 繰り返し参照される設計上決定 | ポリシー、品質基準 |

以下は `rules/` に移さなくてよい:

| 該当するもの | 例 |
|------------|-----|
| 当該スキル固有の手順・実行ステップ | 「Step 1: ○○する」 |
| スキル動作ロジック自体 | 入力検証、出力フォーマット指定 |
| 1 回限りのタスク文脈依存の記述 | — |

## スキル専用コンテンツの `reference/` 分離

`rules/` に移すほど汎用的でなくても、スキル固有のテンプレート・ルール・ガイドラインがインライン記述で長くなる場合 → スキルディレクトリ内 `reference/` サブディレクトリに切り出す。

```
skills/<skill-name>/
├── SKILL.md          ← 参照のみ記載
└── reference/
    └── <content>.md  ← 実体
```

SKILL.md には「`reference/<content>.md` を参照すること」の1行を残す。

## 手順

1. スキル・エージェント記述のルールが上記「移す」基準に該当するか判断
2. ユニバーサルルール → `rules/<topic>/` に切り出す（[[directory-rule]] に従う）
3. スキル専用だが長大なテンプレート・ガイドライン → `skills/<name>/reference/` に切り出す
4. スキル・エージェントファイル内は参照（ファイルパス）のみ残す

## スキル作成フローへの反映確認

**`rules/` に新ルール追加・更新したら、`skills/create-skill/SKILL.md` に反映済みか確認する。**

確認項目:

- 「参照するルール・テンプレート」テーブルにルールパスが載っているか
- 手順中に当該ルールに従う指示があるか

漏れあり → create-skill を更新。

## 参照しても「値」を再掲しない（単一情報源の原則）

`rules/` 参照していても、スキル側に規約**具体値**（`any 不可`・`70/25/5`・`rounded-lg` 等）を再掲 → 二重管理、ルール改訂時に黙ってドリフト。外部化の本質 =「参照すること」でなく「値の唯一の正を `rules/` に保つこと」。

- スキルには**観点名のみ**を索引として残す（例: `命名 / 型 / 定数`、`配色 / 角丸`）。
- 具体値・禁止事項・基準は `rules/` を唯一の正として参照。
- 「該当ルールを読む」手順の後に値を列挙しない（読了後の再掲は冗長）。
- 同じ値が複数スキルに散在 → 横展開で全て参照に寄せる。
- 定義文を `[[rule]]` 参照に置換する際も、参照文の隣に元定義の**言い換え・対応関係を括弧注記として併記しない**（値再掲より見つけにくい重複）。`[[rule]]` 参照、とだけ書けば足りる。

```markdown
❌ エージェント委譲する（＝隔離して呼ぶこと、[[selection-rule]] 参照）
✅ エージェント委譲する（[[selection-rule]]）
```

## 参照例（スキル内の書き方）

```markdown
## ルール

命名規則は [[naming-rule]] (`shared-rules/naming-conventions/naming-rule.md`) に従う。
ファイル配置は [[structure-rule]] (`shared-rules/repository-structure/structure-rule.md`) に従う。
```
