# コンテキストの構成・組み立てルール

コンテキスト = 「一枚の固定文字列」でなく**複数情報部品を整形し並べたもの**として設計。何を・どの高度・どの区切り・どの順に載せるか → 出力品質決定。

対象「文脈の組み立て方」。プロンプト本文自体の構成要素過不足: [[composition-rule]]、区切り敏感さ・頑健性: [[robustness-rule]] 参照（本ルールと役割分担）。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（以下 blog、「効果的なコンテキストの解剖学」）、`documents/reference/context-engineering/a-survey-of-context-engineering-for-large-language-models.md`（以下 survey、§3.1）。

## 1. 適切な「高度（altitude）」を狙う

システムプロンプト・指示 → 2つの失敗モード中間（Goldilocks ゾーン）に置く。

| 極端 | 症状 | 問題 |
|------|------|------|
| 低すぎる高度 | 挙動を脆い if-else ハードコード | 脆弱・保守コスト増。想定外入力で崩れる |
| 高すぎる高度 | 曖昧・一般的すぎる指示。共有文脈を勝手に前提化 | 具体的シグナル無し → 挙動不定 |
| **ちょうどよい** | 挙動を導ける具体性、かつ強力なヒューリスティクスを与えられる柔軟性 | モデル判断力を活かしつつ方向づけ可能 |

- 正確な挙動を1つ残らず条件分岐で書き切ろうとしない。**強いヒューリスティクスを与え判断を委ねる**方向へ寄せる。
- 逆に「良い感じにやって」で済ませない。何を良しとするか具体的シグナルは与える。

## 2. セクションで区切る

プロンプト → 明確区別したセクションに整理、XML タグ・Markdown 見出しで区切る。

- 例: `<background_information>` / `<instructions>` / `## Tool guidance` / `## Output description`。
- 背景・指示・出力仕様を混線させない。
- **注記**: モデル高能力化 → フォーマット厳密さ重要度は逓減。区切り =「モデルが迷わないための補助」、目的ではない。凝った書式に労力を割きすぎない。

## 3. 部品として組み立てる（Format → Concat）

コンテキスト = 次の部品を整形（Format）・連結（Concat）した結果（survey §3.1）。

| 部品 | 中身 |
|------|------|
| c_instr | システム指示・ルール |
| c_know | 外部知識（RAG 取得知識など） |
| c_tools | 使用可能ツール定義 |
| c_mem | 過去やり取りから引き継ぐ記憶 |
| c_state | ユーザー・世界・エージェント系の現在状態 |
| c_query | ユーザー今の要求 |

- 品質決定要因 = 個々の文言だけでない。**部品の選び方・並べ方・整形の仕方**も決める。組み立て方自体を設計対象とする。
- 各部品「このタスクに要るか」で取捨。不要部品を惰性で載せない（→ [[budget-rule]]）。
- 可変入力データ差込時、指示・データ境界を区切りで明示（→ [[robustness-rule]]）。
