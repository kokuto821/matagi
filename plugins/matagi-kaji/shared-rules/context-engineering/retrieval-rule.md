# ランタイムの取得・キュレーションルール

コンテキストは「絶えず進化し続ける情報の宇宙から、限られたウィンドウに何を入れるか」を **実行時に繰り返し選び直す** 営み。関連しそうなデータを全部前もって載せず、必要になった分だけ取りに行く設計が基本。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（以下 blog、「コンテキストの取得とエージェント的検索」）、`documents/reference/context-engineering/a-survey-of-context-engineering-for-large-language-models.md`（以下 survey、§3.1 式4）。

## 1. 検索は「効く」もので選ぶ

取得する知識は、**質問文と表層的に似たもの**でなく**理想の答えに最も効くもの**を選ぶ（survey §3.1、相互情報量の最大化）。

- 類似度スコアが高いだけの断片を集めても、答えに寄与しなければコンテキストの浪費。
- 「この情報が無いと答えが出ないか？」で採否を判断。

## 2. ジャストインタイム取得（just in time）

全データを事前処理してコンテキストに載せない。**軽量な識別子**（ファイルパス・保存済みクエリ・Web リンクなど）を保持し、ツールで実行時に必要分だけ読み込む。

- 例：`head` / `tail` / `grep` / `glob` でデータ全体を載せず大量データを扱う。Claude Code の大規模データ分析はこの方式。
- 人間の認知に近い。全部暗記せず、ファイルシステム・受信トレイ・ブックマークといった外部索引を使い、必要時に取りに行く。
- **トレードオフ**：実行時探索は事前取得より遅い。モデルが情報の景観を辿る適切なツールとヒューリスティクスも要る。ガイダンスなしだと、ツール誤用・行き止まり追跡・重要情報の取りこぼしで、かえってコンテキストを浪費。

## 3. 漸進的開示（progressive disclosure）

エージェントに自律的にデータを辿らせ、**探索を通じて関連文脈を一層ずつ発見**させる。

- メタデータ自体がシグナル：フォルダ階層・命名規則・タイムスタンプ・ファイルサイズが「いつ・どう使うべきか」を示唆（例：`tests/test_utils.py` と `src/core_logic/` の同名ファイルは用途が違う）。
- 各やり取りが次の判断の文脈を生む。作業記憶には必要なものだけ残し、残すべき決定は [[long-horizon-rule]] のノート取りへ逃がす。

## 4. ハイブリッド戦略

速度のため一部を事前ロードし、残りは自律探索で補う。

- Claude Code は `AGENTS.md`/`CLAUDE.md` を素朴に事前投入する一方、`glob` / `grep` で環境を辿りファイルをジャストインタイム取得（古い索引や複雑な構文木の問題を回避）。
- 変動の少ない領域（法務・金融など）ほど事前ロード寄りが向く。
- 迷ったら **「うまくいく最もシンプルなことをせよ（do the simplest thing that works）」**。モデルの能力向上に伴い、人手のキュレーションは減らす方向でよい。
