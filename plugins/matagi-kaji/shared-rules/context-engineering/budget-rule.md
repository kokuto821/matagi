# コンテキストは有限資源のルール

コンテキスト（推論時に載るトークン集合）= 無限に足せる入力でなく **限界収穫逓減する有限資源**。スキル・エージェント・AGENTS.md/CLAUDE.md・単発プロンプトいずれの設計も、この前提から出発。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（以下 blog、「なぜ重要か」「効果的なコンテキストの解剖学」）、`documents/reference/context-engineering/a-survey-of-context-engineering-for-large-language-models.md`（以下 survey、§3.2.1 / §4.3.1）。

## 原則：高シグナルなトークンの最小集合を狙う

**望ましい結果の実現可能性を最大化する、高シグナルなトークンの最小集合を探す。**

- **「最小」＝「短い」ではない。** 望ましい挙動を確実に守らせるのに必要な情報は前もって十分に与える。削って挙動が崩れるなら最小集合ではない。
- **まず最小で測り、失敗モードを見て足す。** 利用可能な最良モデルで最小限プロンプトを試す → 実際の失敗確認 → 明確な指示・例を **狙って** 追加。想像上のエッジケースを先回りで詰め込まない。
- **惰性で足さない。** 要素を1つ足すたび「このタスクに本当に効くか」を問う。必要情報だけに絞れば少トークンで同等品質（survey §3.2.3）。

## 背景：注意予算と context rot

「多いほど良い」不成立の理由。

- **注意予算（attention budget）**：LLM は大量コンテキスト解釈に有限「注意」を消費。新トークン投入ごと予算減。
- **context rot**：コンテキスト内トークン増加 → 正確想起能力は低下。程度差こそあれ全モデルに現れる。
- **構造的理由**：Transformer は n トークンで n² 通りペア関係 → 長いほど注意が薄く引き伸ばされる。加えて訓練分布は短系列が多く、長距離依存の経験・専用パラメータが少ない。位置エンコーディング補間も長系列で劣化を伴う。断崖でなく **性能の勾配（グラデーション）** 発生。
- **中盤の脱落（lost-in-the-middle）**：長い入力の中盤に置いた情報は抜け落ちやすい（survey §4.3.1）。重要な指示・データを長文中央に埋めない。

上記は「詰め込めば賢くなる」直感を否定。ゆえに載せるトークンを慎重キュレーションする価値あり。

## 適用の指針

- プロンプト／ルール／AGENTS.md/CLAUDE.md が長い → まず「削れるトークン」を疑う。冗長前置き・重複説明・未使用例を削る。
- 常時ロード対象（AGENTS.md/CLAUDE.md・未スコープ rule）ほど予算影響大。手順 → skill、限定的文脈 → path スコープ・`[[link]]` 参照へ寄せる（→ `[[selection-rule]]`）。
- 「最小十分」判断不能 → 削った版・足した版を実際に走らせ挙動差確認。
