# ツール設計とコンテキスト効率のルール

ツール = エージェント・情報／行動空間間の **契約**。ツールセット設計 → そのままコンテキストの信頼できる保守・剪定に効く。よく設計されたコードベース関数と同じ規律で設計。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（「効果的なコンテキストの解剖学」→ツール）。

## 1. 必要最小限のツールセットにする

- **肥大化を避ける**。機能を広く抱えすぎ、機能重複、どれを使うべきか判断曖昧なツールセット = 失敗モード。
- 判断基準：**ある状況で人間のエンジニアがどのツールを使うべきか断定できないなら、AI エージェントにそれ以上は期待できない**。選択曖昧 → まずツールセットを絞る／統合する。
- 実用最小限へ絞る → 長い対話にわたるコンテキストをより信頼できる形で保守・剪定可能（→ [[long-horizon-rule]]）。

## 2. トークン効率のよいツールにする

ツールは2つの意味で効率を推進：**トークン効率良い情報を返す**・**効率的エージェント挙動を促す**。

- **自己完結・エラー耐性・用途が極めて明確**。よく理解でき機能重複最小のツールを作る。
- **入力パラメータは記述的・曖昧さなし**。モデルが本来持つ強みを活かせる形。
- **返り値もトークン効率良く**。生の巨大出力をそのまま返さず必要情報に絞る（大量データはツール側で `head`/`tail`/クエリ等に寄せる。→ [[retrieval-rule]]）。
