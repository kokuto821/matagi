# 長時間軸タスクの管理ルール

トークン数がウィンドウ超過の一連作業（大規模移行、包括的リサーチなど）で首尾一貫性・目標指向を保つ技法。どれだけ大きなウィンドウでも context pollution（文脈汚染）・情報関連性劣化は免れないため、ウィンドウ制限に正面から対処。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（以下 blog、「長時間軸タスクのためのコンテキストエンジニアリング」）、`documents/reference/context-engineering/a-survey-of-context-engineering-for-large-language-models.md`（以下 survey、§4.3.3 / §5.4）。

## 1. 早期コンパクション（compaction）

コンパクション = 上限近い会話を要約 → 要約で新ウィンドウ再初期化 → 作業継続する実践。要約は高忠実度蒸留。性能劣化を抑え連続性維持。

**本 kit 運用方針（原典からの差分）**：Claude Code は `/compact` 組み込み、上限直前で自動発火もする。ただし本 kit は **上限直前の自動発火を待たず、コンテキスト消費 50% 前後の自然な区切りで、通常より早期に手動 `/compact`** を推奨。context rot は勾配的進行のため（→ [[budget-rule]]）、上限ぎりぎりまで引っ張るより早めに畳むほうが想起精度を保ちやすい。

残す/捨てる判断 = 技芸の核心：

- **残す**：アーキテクチャ上の決定、未解決バグ、実装詳細。
- **捨てる**：冗長ツール出力、繰り返しメッセージ。最安全・軽量形 =「一度使い終えたツール呼び出し・結果の消去」。
- **要約プロンプト調整順**：まず recall（再現率）最大化 → あらゆる関連情報を捉える、その後 precision（適合率）向上 → 余分を削る。過度に積極的な圧縮 → 後で効く微妙な文脈を喪失。
- 適するタスク：広範な往復（back-and-forth）要、会話の流れ維持が重要なもの。

## 2. 構造化ノート取り（structured note-taking / agentic memory）

ウィンドウ外メモリへノートを定期書き出し → 後でウィンドウに引き戻す技法。最小オーバーヘッドで永続メモリ獲得。

- 例：Claude Code の ToDo リスト、カスタムエージェントの `NOTES.md`。数十回のツール呼び出し間で失われがちな決定・依存関係を保持。
- コンテキストリセット越しでも、自ノート読み直しで作業継続可能。
- **特に有効な場面**：明確マイルストーンの反復開発、**複数メインコンテキストウィンドウを順次使い切る大規模タスク**。各ウィンドウ終わりに要点をノートへ退避 → 次ウィンドウ冒頭で読み戻し → ウィンドウ越し長時間軸戦略が成立。

## 3. サブエージェント・アーキテクチャ

1エージェントで全状態を抱えず、専門化サブエージェントが **クリーンなコンテキストウィンドウ** で焦点を絞ったタスクを処理。

- サブエージェントは数万トークン使い広く探索しても、返却は **凝縮・蒸留した要約（多くは 1,000〜2,000 トークン）** のみ。
- メインエージェント = 高レベル計画・統合・分析に専念（明確な関心分離）。詳細検索文脈はサブエージェント内に隔離。
- 適するタスク：並列探索が配当をもたらす複雑リサーチ・分析。
- 「隔離したい副次タスクは subagent へ」という **置き場所** 判断、「スキル起動（in-context 実行）／エージェント委譲（隔離起動）」用語定義は [[selection-rule]] を唯一の正として参照（再掲しない。[[externalization-rule]]）。本ルールはその上で **クリーン文脈での並列探索＋蒸留要約** という長時間軸戦略の使いどころを扱う（役割分担）。

## 3技法の使い分け

| 技法 | 向いているタスク |
|------|----------------|
| コンパクション | 広範な往復要、会話の流れ維持したい |
| ノート取り | 明確マイルストーンの反復開発／複数ウィンドウ順次活用の大規模作業 |
| サブエージェント | 並列探索が効く複雑リサーチ・分析 |

いずれもタスク特性で選択。排他でなく組み合わせ可。
