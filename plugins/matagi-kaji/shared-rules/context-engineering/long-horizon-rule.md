# 長時間軸タスクの管理ルール

トークン数がコンテキストウィンドウを超える一連の作業（大規模な移行、包括的リサーチなど）で、首尾一貫性・目標指向を保つ技法。どれだけ大きなウィンドウでも context pollution（文脈の汚染）や情報の関連性劣化は免れない。ウィンドウ制限に正面から対処する。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（以下 blog、「長時間軸タスクのためのコンテキストエンジニアリング」）、`documents/reference/context-engineering/a-survey-of-context-engineering-for-large-language-models.md`（以下 survey、§4.3.3 / §5.4）。

## 1. 早期コンパクション（compaction）

コンパクションは、上限に近づいた会話を要約し、その要約で新しいウィンドウを再初期化して作業を続ける実践。要約は高忠実度の蒸留。性能劣化を抑えて連続性を保つ。

**本 kit での運用方針（原典からの差分）**：Claude Code には `/compact` が組み込まれ、上限直前で自動発火もする。ただし本 kit は **上限直前の自動発火を待たず、コンテキスト消費が 50% 前後に達した自然な区切りで、通常より早期に手動 `/compact`** を推奨。context rot は勾配的に進むため（→ [[budget-rule]]）、上限ぎりぎりまで引っ張るより早めに畳むほうが想起精度を保ちやすい。

何を残し何を捨てるかが技芸の核心：

- **残す**：アーキテクチャ上の決定、未解決のバグ、実装の詳細。
- **捨てる**：冗長なツール出力、繰り返しのメッセージ。最も安全で軽い形は「使い終えたツール呼び出しとその結果の消去」。
- **要約プロンプトの調整順**：まず recall（再現率）最大化であらゆる関連情報を捉え、その後 precision（適合率）を上げて余分を削る。過度に積極的な圧縮は、後で効く微妙な文脈を失わせる。
- 適するタスク：広範な往復（back-and-forth）を要し、会話の流れの維持が重要なもの。

## 2. 構造化ノート取り（structured note-taking / agentic memory）

ウィンドウ外のメモリへノートを定期的に書き出し、後でウィンドウに引き戻す技法。最小のオーバーヘッドで永続メモリを得る。

- 例：Claude Code の ToDo リスト、カスタムエージェントの `NOTES.md`。数十回のツール呼び出しの間に失われがちな決定・依存関係を保つ。
- コンテキストのリセットをまたいでも、自分のノートを読み直して作業継続可能。
- **特に有効な場面**：明確なマイルストーンを持つ反復開発、そして **複数のメインコンテキストウィンドウを順次使い切る大規模タスク**。各ウィンドウの終わりに要点をノートへ退避し、次ウィンドウの冒頭で読み戻すと、ウィンドウをまたぐ長時間軸の戦略が成立。

## 3. サブエージェント・アーキテクチャ

1つのエージェントで全状態を抱えず、専門化したサブエージェントが **クリーンなコンテキストウィンドウ** で焦点を絞ったタスクを処理する。

- サブエージェントは数万トークンを使って広く探索しても、返すのは **凝縮・蒸留した要約（多くは 1,000〜2,000 トークン）** のみ。
- メインエージェントは高レベルの計画・統合・分析に専念（明確な関心の分離）。詳細な検索文脈はサブエージェント内に隔離。
- 適するタスク：並列探索が配当をもたらす複雑なリサーチ・分析。
- 「隔離したい副次タスクは subagent へ」という **置き場所** の判断、および「スキル起動（in-context 実行）／エージェント委譲（隔離起動）」の用語定義は [[selection-rule]] を唯一の正として参照（再掲しない。[[externalization-rule]]）。本ルールはその上で、**クリーン文脈での並列探索＋蒸留要約** という長時間軸戦略としての使いどころを扱う（役割分担）。

## 3技法の使い分け

| 技法 | 向いているタスク |
|------|----------------|
| コンパクション | 広範な往復を要し、会話の流れを保ちたい |
| ノート取り | 明確なマイルストーンの反復開発／複数ウィンドウを順次活用する大規模作業 |
| サブエージェント | 並列探索が効く複雑なリサーチ・分析 |

いずれもタスク特性で選ぶ。排他でなく組み合わせ可。
