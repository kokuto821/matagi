# レビュー重大度ルール

## 原則

**レビュー結果の優先度は Critical / Warning / Suggestion の3段階で示す。** 3段階の名称と本質的な意味は本ルールを唯一の正とし、各レビュアー（skills / agent）側で定義を再掲しない。ドメイン固有の該当例のみ各レビュアーに残す。

## 3段階の定義

| 段階 | 本質 |
|------|------|
| **Critical** | 破られると機能・品質・タスクの成立・保証すべき制御を損なう、または明確なルール違反。最優先で対処。 |
| **Warning** | 規約・意図からの逸脱だが、影響が局所的なもの。 |
| **Suggestion** | より規約・意図に沿わせる改善提案。 |

## 適用手順

1. レビュー結果を上記3段階に分類、Critical → Warning → Suggestion の順に並べる。
2. 各指摘に「該当箇所（`file:line`）／ 根拠ルールのパス ／ 問題点 ／ 修正の方向性」を併記。
3. 段階の意味は本ルールに委ね、レビュアー側には**そのドメインで何が Critical に当たるかの該当例**のみ残す（例: UI なら「アクセシビリティを損なう」、プロンプトなら「タスクが伝わらない」）。
4. 指摘が無ければ「（対象）ルール準拠で問題なし」と明記。

## やってはいけないこと

- 各段階の一般的な定義文（「規約逸脱だが局所的なもの」等）をレビュアー側に再掲する。値の二重管理でドリフトする（[[externalization-rule]] §単一情報源）。

## 背景

Critical / Warning / Suggestion の3段階は、frontend / ui / prompt / steering など複数のレビュー系 skills・agent で共通使用。各所に定義を再掲した結果、Warning・Suggestion の文言が既にファイル間でずれ始めたため、単一情報源として切り出した。
