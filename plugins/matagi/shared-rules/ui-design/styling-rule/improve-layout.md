    - ナビゲーション
    - ページヘッダー
    - コンテンツエリア
      - ２カラムで副次的な情報を掲載可
  - すべてのページで一貫性を持たせる
- モバイル
  - レイアウト
    - ヘッダー
    - ページヘッダー
    - コンテンツエリア
    - ボトムナビゲーション
  - 操作はシンプルに基本は１カラム
  - 幅いっぱいに広げるフルードレイアウト
- 画面に情報を詰め込みすぎない
  - 余白を大きく文字にメリハリを
  - ボタンは少なく、主要な操作はなるべく1つに
  - 業務利用アプリは余白を減らし情報量を多くした方が使い勝手が良い場合あり
- 視線の流れに沿う
  - Z型
    - 削除などネガティブなボタンはあえて左下において印象を薄めることもある
  - F型
    - サイドナビゲーションが置かれている場面、SNS
    - 読み飛ばされないよう重要なものはリスト先頭に配置する
- 画面のグループ分けと情報の精査
  - グループ化し優先順位をつける
  - グループ化で項目をまとめる
  - 優先順位を決めて、強弱をつける
- 余白と罫線
  - 余白を適度に取り入れる
    - 罫線をなくして、代わりに余白を使う
    - 罫線の色を控えめにする
  - 罫線使いすぎ×
    - 画面が複雑
    - 罫線は画面の構造をわかりやすくしたいときに活用する
      - 大項目の区切り
    - 余白と罫線の間の選択肢としてグレーエリアを使う
- テキストは画面いっぱいにしない
  - 横方向に長いと読みにくい
  - 最大の幅を決めて、改行させる
  - コンテンツ幅で改行位置を調整する
    - 左右の余白に自由の利く画面であればコンテンツ幅を調整する
- 画面サイズが小さいときを考慮する
  - 文言を省略、優先度の低いものを非表示
    - 最初の方が読めれば問題ない場合が多い
  - ボタンはドロップダウンメニューに格納する
- 多言語化を考慮する  
  - 文字量が増えても大丈夫なように、余白を開けておく
  - アイコンボタンを利用すると多言語対応時にレイアウトが崩れにくい
  - 行間と字間の最適解は言語によって異なる
    - 日本語 letter-spacing:-0.4px
    - 英語　letter-spacing:-0.1px
- 一覧を見やすくする
  - 項目に強弱をつける
    - 見出しは大きく
    - 横並びにせず配置を工夫する
  - 全部の情報は出さなくて良い
  - 横並び以外のレイアウトも考える
  - 一覧上に置くボタンを隠す
    - ホバーしたときに出る
  - 一覧画面のパターン
    - リストバー型
      - 1枚のアイテムを自由なレイアウトで配置する
      - 迷ったらおすすめ
    - テーブル型
      - 会計明細や統計データ等
    - カード型 
      - ECサイト等写真を大きく見せたいときに〇
      - 文字情報は少なくなる
  - 一覧と詳細を同時に表示するパターン
    - 左右分割型
      - 左のリストを選ぶと、右の詳細が切り替わるパターン
    - 上下分割型
      - モバイルでよく使われる
    - ミニウィンドウ型
      - 詳細がウィンドウで表示されるパターン
- 詳細画面の表示パターン
  - 詳細を1ページとする
    - 基本形
    - 多くの情報を掲載できる
    - 旅行・料理アプリ等の写真を使った複雑なコンテンツには〇
    - メリット
      - 詳細画面だけに操作を集中できる
      - 広い画面を使い、多くの情報が掲載できる
      - 固定のURLから直接リンクさせやすい
    - デメリット
      - 必ず画面遷移を伴うので、複数の詳細画面を確認する作業が難しい
    - 詳細画面の表示パターンは共存も可能
  - 詳細を右パネル
    - メリット
      - 連続して閲覧する操作がしやすい
      - 画面遷移を伴わないため、操作が快適に感じる
    - デメリット  
      - エリアが小さく、複雑なコンテンツを置けない
      - モバイルアプリでは画面が小さく、採用できない
      - 固定のURLからのリンクが実装しにくい
  - 詳細をモーダル
    - メリット
      - 画面遷移を伴わないため、一覧に簡単に戻れる
      - 気軽な操作感
    - デメリット
      - 簡単にウィンドウを閉じれるため、複雑な操作には向かない
      - 固定のURLからのリンクが実装しにくい
- スクロール範囲のコツ
  - スクロール範囲を区切り線などで明確にする
  - サイドナビゲーションは別スクロールに
  - スクロール領域内に別スクロール領域を作らない
    - 可能ならレイアウトを調整してエリアを分ける
  - スクロールを固定する
    - ヘッダー
    - ページヘッダー
    - タブ、ナビゲーション
    - 下部の操作ボタン
    - 編集ツールのエリアのボタン
  - スクロールバーの見た目を調整する
  - 横スクロール
    - モバイルではスワイプで簡単に行えるので有効
    - 描画系のアプリでは縦横両方にスクロールする
      - 縦横の現在位置がわかるようにスクロールバーを配置
      - ドラッグ操作できると〇
  - スクロールを促す
    - スクロールさせるために少しだけ画面を見せる
  - スクロールを使わない方がいいパーツ
    - スクロールでアプリ全体が使いにくくなる場合は代案を考える
- 管理設定画面専用のレイアウトを用意する
  - 設定・管理画面はメイン機能とは別物で特に管理画面は別物であると考える
  - メイン機能とは別の見た目にする
  - 管理画面定番
    - サイドナビゲーションで設定項目を分散
    - モバイルではカテゴリ一覧があり、設定の詳細に移動
