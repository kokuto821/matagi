- デバイスごとに操作しやすい方法を考える
  - デスクトップアプリ=全体像が見えるように
  - モバイルアプリ=集中しやすいように
- やることの導線を明確にする
  - タスク型×
    - やることを選んでから対象を選ぶ
  - オブジェクト型〇
    - 一覧で対象を選んでからやることを選ぶ
  - 必要アクションを列挙しない
    - タスク型→自由度が低くなる
  - 対象オブジェクトの洗い出しを先に行う
- リンクとページタイトルの表記を合わせる
- 複数の画面のデータは同期する
- 文言を洗練させる
  - 簡潔・伝わりやすい
  - 敬語は使いすぎない
  - 「全て」等読みにくい言葉はひらがなに
  - なじみある言葉に変換
  - ボタンは動作名にする
  - 同じ意味の言葉は統一する
  - 次の行動を促す
- なくてもわかるものは削る
  - メルアド、金額、日付などは文字だけで伝わる
- 文章に置き換える
  - 更新日時：12:30→25分前に更新〇
- 文字以外の表現方法を考える
- ユーザへのフィードバックをする
  - 画面全体に関わる処理=トーストを使う
  - 項目の近くでフィードバック
  - 処理が長いとき=実行中とわかるようにする
- エラーの表現
  - エラー箇所がわかりやすいように
    - 場所と原因が明確
  - 視覚的な強調
  - 具体的な行動を促すメッセージ
- 省略を用いる
  - ヘッダータイトルの文字省略
    - 高さ固定優先で右端で省略
  - 内包する件数を出すようにする
  - グラデーションによる省略
- サムネイルで識別を助ける
  - 画像あり→対象を探しやすい
  - サムネイルは小さくても良い
  - カード型=大きくサムネイル表示可
  - サムネイルにできないものはアイコンを用いる
- 危険な操作の前は必ず確認を入れる
  - 確認ダイアログを一度挟みユーザーが安心して利用できるようにする
  - 誤解のないようにする
  - JSのConfirmはなるべく使わない
- 重要な意思決定のボタンは操作前に情報を知らせる
  - 文言を調整し補足をつける
  - レジに進む＋注文はまだ確定していません
  - 補足テキストorモーダル
  - まだ確定していないことを知らせることも大事
- 0件表示（empty state）は必ず用意する
  - 次の操作を書くとより良い
  - イラスト・図を配置
- 初回ユーザー向けの案内を用意する
  - コーチマーク
  - 説明モーダル
  - 説明ツールチップ
  - パーソナライズ
  - サンプル
  - ミッション
  - ウォークスルー
  - マニュアル無しで使えることを目指す。マニュアルは困ったときの最終手段
- よく使う操作を手前に
  - ベストなソート順か考える
  - ユーザーが自由に管理できるように
- ステータスをわかりやすく
  - 状態には一貫性を持たせる
  - 複数ステータスが成り立つよう設計
- クリック範囲をわかりやすく
  - クリック可範囲の枠・背景色を調整
  - 文字だけのリンクは特に注意
  - hover時にボタン・文字を出す
  - 適切なCursorを用いる
- 有効なアニメーションをつける
  - 空間の認識を助ける
  - コンパクトなものを広げる
  - 隠れているものを表示する
  - ドラッグ操作、スワイプ操作と必ず動きを合わせる
  - 動きは双方向
  - 気づきを与える
    - 通知が来たときに受信箱をバウンドさせる
    - チャットの入力中に動きのあるアイコンを用いる
    - 完了メッセージトーストを表示する
    - 注目させたい数字をカウントアップする
- アニメーションは要所に絞り速く動かす
  - アニメーションは0.1~0.3秒 が基本。長くても0.5秒
  - アニメーションなしの方が効果的な場合もある
