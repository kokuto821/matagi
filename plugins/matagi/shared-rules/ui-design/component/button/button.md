# button
-　特定操作開始・システム処理実行パーツ
- 全画面で利用、ユーザー意思決定担うためアプリ内最重要パーツの1つ
## 原則
- 重要度でデザイン変更
  - 主要機能・意思決定ボタン=目立たせ、補助操作ボタン=控えめ→使い勝手向上
  - アプリ全体で同一ルール徹底
- ボタン配置で優先度調整
  - 視線誘導の観点、画面上配置で操作しやすさ変化
  - 左上
    - 視線誘導の最初→目に入りやすい
    - 一方操作しにくい→優先度高ボタンは置かない
    - 戻るボタン等を置く
  - 左下
    - 操作しにくい
    - 削除等ネガティブボタンを置く
  - 右上
    - 操作しやすい
    - 画面全体に対する操作ボタンを置く
    - 何か開始するボタン配置に適す
  - 右下
    - 操作しやすい
    - 視線誘導の最終地点→「保存」等最終実行ボタン配置に適す
    - フローティングボタン
      - 主にモバイル
      - 常に親指で押しやすい位置に固定表示
      - 使用頻度高機能に用いる
- 非活性
  - 押せないことを表現
  - 半透明かグレー
  - 使えないボタン→押してエラーにせず、先に非活性
## ボタン定義の例
  - primary
    - 画面最重要操作
    - 操作確定する意思決定ボタンには必ず用いる
    - 保存・OK
  - Secondary
    - 主要機能でないボタン
    - 何かしら操作開始時のボタン
    - 1ページ内に複数置ける
    - ネガティブなボタン
      - 「キャンセル」「クリア」等
      - 危険度高→別種類ボタンを検討
  - Teritary
    - Secondaryボタンより弱く見せたい場合
    - 1ページ内に複数置ける
  - アイコンボタン
    - Secondaryボタンと同用途、画面レイアウト上コンパクト表示したい場合
    - PC画面ではオンマウス時に必ずツールチップでボタン名称表示
