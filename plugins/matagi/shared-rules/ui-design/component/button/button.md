# button
-　特定の操作を開始したり、システムの処理を実行するパーツ
- あらゆる画面で利用、ユーザーの意思決定を担うため、アプリ内で最重要パーツの1つ
## 原則
- 重要度によってデザインを変える
  - 主要機能・意思決定のボタンは目立たせ、補助操作のボタンは控えめにして使い勝手向上
  - アプリ全体で同一ルールを徹底
- ボタンの配置で優先度を調整する
  - 視線誘導の観点から、画面上の配置で操作しやすさが変わる。
  - 左上
    - 視線誘導の最初のため、目に入りやすい
    - 一方で操作しにくく、優先度の高いボタンは置かない
    - 戻るボタン等を置く
  - 左下
    - 操作しにくい
    - 削除等のネガティブなボタンを置く
  - 右上
    - 操作しやすい
    - 画面全体に対する操作ボタンを置く
    - 何かを開始するボタンの配置に適す
  - 右下
    - 操作しやすい
    - 視線誘導の最終地点のため、「保存」等の最終実行ボタンの配置に適す
    - フローティングボタン
      - 主にモバイル
      - 常に親指で押しやすい位置に固定表示
      - 使用頻度が高い機能に用いる
- 非活性
  - 押せないことを表現
  - 半透明にするかグレーにする
  - 使えないボタンは押してエラーにせず、先に非活性にする
## ボタン定義の例
  - primary
    - 画面の最も重要な操作
    - 操作が確定する意思決定のボタンには必ず用いる
    - 保存・OK
  - Secondary
    - 主要な機能ではないボタン
    - 何かしらの操作を開始するときのボタン
    - 1ページの中に複数置くことができる
    - ネガティブなボタン
      - 「キャンセル」「クリア」等
      - 危険度が高ければ別種類のボタンを検討
  - Teritary
    - Secondaryボタンより弱く見せたい場合
    - 1ページの中に複数置くことができる
  - アイコンボタン
    - Secondaryボタンと同じ用途だが、画面レイアウト上にコンパクトに表示したい場合
    - PC画面ではオンマウス時に必ずツールチップでボタン名称を表示
