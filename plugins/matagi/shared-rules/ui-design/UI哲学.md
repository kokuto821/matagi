# UI/UX哲学

## UI＝美しさ＞使いやすさ
- 美しさ → 直感性向上 → 結果的な効率向上
- 美しいUIは「より使いやすいと知覚」されやすい。軽微な不便の許容、操作を速く感じる効果あり

## 美しさとは？
- 心を動かし、記憶に残る視覚体験
  - 一貫したデザイン規則・哲学
  - 見るだけで「好き」「使いたい」「所有したい」という欲求が生まれる
  - プロダクト特有の独自の世界観を表現している
- シンプルで機能的である
  - 無駄がない
  - 文字情報より記号で表現することを優先する
- 説明がなくても直感的に操作できる
- 動的な表現の使用
  - アニメーションは大胆なものに限らず、ホバー等の小規模なものも含む
  - アニメーションで状態変化が伝わりやすくなる
  - 感情への訴えに高い効果

## ゲームのUI哲学を取り込む
- ゲームUIはユーザー満足度・継続度を高める天才
  - 目的達成までの判断が容易で直感的
- 業務用アプリも真似すべき

## UX＝楽しく問題解決できるか
- 楽
  - 楽しくプロダクトを利用する
  - 楽に問題解決する
  - この２つの「楽」でパフォーマンスを向上させる
- 個人の好みや特性をカバーする機能設計＝カスタマイズ性の高さ を実現
  - userConfig
  - Theme切り替え
- ストレスを感じず、問題を楽に解決して満足していることが理想
- 美しさ（洗練されたUI）も満足度・定着率・採用率に明確に寄与

# 実践例
- 個人的なこだわり色覚異常者や左利きなど少数派にも優しいUI
- どの種類の色覚異常者にとっても判別しやすい配色にする
- 左利き向けにLeftモードボタンを実装
  - L/Rボタンで切り替え

## テーマ
- コンポーネントの見た目パターンを複数用意し、テーマ切り替えで個人好みのUIにカスタマイズ可能にする
  - CSS等デザイン設定はほぼすべてThemeで管理。コンポーネント側は使うだけにする
  - ユーザーごとの好みの配色にすぐ変更可能。トレンドUI（Neumorphism・ノスタルジックUI）もボタン1つで切り替え可能にする

### テーマ設計の具体化
- テーマが管理する変数は「色」＋「影・光」
- サイズ・余白・角丸・構造はテーマに含めない
- テーマは3層に分類する
  - 標準テーマ（アクセシビリティ全対応）
  - トレンドテーマ（視覚優先・アクセシビリティ非保証）
  - アクセシブルテーマ（特定ユーザー向け最適化）
- マインクラフトのスキンやテクスチャパック、VisualStudioCodeのテーマなどから着想

### 記号優先のフォールバック階層
- 自明な記号 → そのまま
- やや曖昧 → ホバーでツールチップ
- 曖昧 → ラベル常時表示
- 複雑な概念 → ？ボタン

### 哲学の役割分担
- 「何を作るか・何を削るか」はPM・デザイナーの領域
- 「どう作るか・実装の質」でUI哲学を表現する
