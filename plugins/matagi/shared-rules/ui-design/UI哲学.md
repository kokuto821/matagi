# UI/UX哲学

## UI＝美しさ＞使いやすさ
- 美しさ → 直感性向上 → 結果的な効率向上
- 美しいUI→「より使いやすい」と知覚されやすい。軽微な不便許容、操作を速く感じる効果あり

## 美しさとは？
- 心動かし記憶残る視覚体験
  - 一貫したデザイン規則・哲学
  - 見るだけで「好き」「使いたい」「所有したい」欲求発生
  - プロダクト特有の独自世界観を表現
- シンプル・機能的
  - 無駄がない
  - 文字情報より記号表現を優先
- 説明なしでも直感操作可
- 動的表現の使用
  - アニメーション=大胆なものに限らず、ホバー等小規模も含む
  - アニメーション→状態変化が伝わりやすい
  - 感情訴求に高効果

## ゲームのUI哲学を取り込む
- ゲームUI=ユーザー満足度・継続度を高める天才
  - 目的達成までの判断が容易・直感的
- 業務用アプリも真似すべき

## UX＝楽しく問題解決できるか
- 楽
  - 楽しくプロダクト利用
  - 楽に問題解決
  - この２つの「楽」→パフォーマンス向上
- 個人の好み・特性をカバーする機能設計＝カスタマイズ性の高さ を実現
  - userConfig
  - Theme切り替え
- ストレスなし・問題を楽に解決・満足 が理想
- 美しさ（洗練UI）も満足度・定着率・採用率に明確寄与

# 実践例
- 個人的こだわり: 色覚異常者・左利き等少数派にも優しいUI
- 全種類の色覚異常者が判別しやすい配色にする
- 左利き向けLeftモードボタン実装
  - L/Rボタンで切り替え

## テーマ
- コンポーネント見た目パターン複数用意→テーマ切り替えで個人好みUIにカスタマイズ可能にする
  - CSS等デザイン設定ほぼ全てTheme管理。コンポーネント側は使うだけ
  - ユーザー毎好みの配色へ即変更可。トレンドUI（Neumorphism・ノスタルジックUI）もボタン1つで切り替え可能にする

### テーマ設計の具体化
- テーマ管理変数=「色」＋「影・光」
- サイズ・余白・角丸・構造=テーマに含めない
- テーマ3層分類
  - 標準テーマ（アクセシビリティ全対応）
  - トレンドテーマ（視覚優先・アクセシビリティ非保証）
  - アクセシブルテーマ（特定ユーザー向け最適化）
- マインクラフトのスキン・テクスチャパック、VisualStudioCodeのテーマ等から着想

### 記号優先のフォールバック階層
- 自明な記号 → そのまま
- やや曖昧 → ホバーでツールチップ
- 曖昧 → ラベル常時表示
- 複雑な概念 → ？ボタン

### 哲学の役割分担
- 「何を作るか・何を削るか」=PM・デザイナー領域
- 「どう作るか・実装の質」でUI哲学を表現
