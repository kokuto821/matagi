# 目的

ユーザーから提供された変更内容や指示をもとに、一貫したフォーマットの日本語コミットメッセージを生成する。同時に、複数の異なる意味を持つ変更が含まれている場合は、それらを適切に論理的な単位で分割して提案する。

# コミット分割のルール

- 1つのコミットには1つの論理的な変更のみを含める（例：「機能追加」と「無関係なバグ修正」、または「リファクタリング」と「機能追加」などを分ける）。
- 変更点（diff）の中に複数の意図が混在している場合、プレフィックスごとにコミットを分割すること。

# フォーマット

各コミットメッセージは以下の形式に厳密に従うこと。

`#<issue番号> <prefix>: <○○>のため<△△>する`

- `#`: 固定のリテラル文字。issue番号の有無に関わらず必ず先頭に付ける。
- `<issue番号>`: 現在のブランチ名から抽出した issue 番号（数字）、または抽出できない場合は `x`。手順は下記「issue番号の取得」。
- `<prefix>`: 下記のプレフィックス一覧から適切なものを一つ選択する。
- `<○○>`: 変更の「目的」や「理由」を簡潔に記載する。
- `<△△>`: 具体的な変更の「内容」や「手段」を簡潔に記載する。

例:
- 抽出できた場合: `#51 feat: ユーザー管理のためログイン機能を追加する`
- 抽出できない場合: `#x fix: 表記揺れ解消のためラベルを修正する`

## issue番号の取得

- `git branch --show-current` で現在のブランチ名を取得する。
- ブランチ名の命名規則は [[issue-driven-rule]]（`shared-rules/issue-driven-development/issue-driven-rule.md`）を唯一の正とし、本節では再掲しない。**issue-driven-rule のブランチ命名規則（区切り文字・順序）を変更する場合は、下記の抽出手順も合わせて更新すること。**
- 抽出手順: ブランチ名が正規表現 `^[^/]+/#(\d+)_` に一致すれば、キャプチャした数字を issue 番号とする。
- 一致しない場合（`#` が無い、`#` の直後が数字でない、`_` 区切りが無い等、境界ケースをすべて含む）は、issue番号の位置に `x` を使う。

# プレフィックス一覧

- `feat`: 新しい機能を追加
- `fix`: バグ修正
- `refactor`: コードのリファクタリング
- `style`: コードの見た目やフォーマットを修正 (機能に影響なし)
- `test`: テストコードの追加や修正
- `docs`: ドキュメントの修正や追加
- `chore`: ビルドやツール関連の変更
- `remove`: ファイルや機能の削除
- `rename`: ファイル名の変更

遷移は図に従い、判定基準・詳細は下の本文に従う。

凡例: 黄 = ユーザーの確認・承認

1. `git branch --show-current` で現在のブランチ名を取得し、「issue番号の取得」の手順で issue番号（または `x`）を確定する。
2. 対象となる変更内容（diffや説明）を分析し、変更の意図が複数混ざっていないか（分割すべきか）を判断する。
3. 分割が必要な場合は、対象ファイルや変更内容を論理的なグループに分ける。
4. グループごとに最も適したプレフィックスを選択する。
5. グループごとに、変更が「なぜ行われたのか（○○）」と「何を行ったのか（△△）」を把握する。
6. `#<issue番号> <prefix>: <○○>のため<△△>する` という構成の1行のメッセージを作成する。手順1で確定した issue番号（または `x`）を全コミットに共通で使う。
7. 分割の有無にかかわらず、**必ず実際のコミット処理を行う前**に、「どのようなファイル構成で、どのようなコミットメッセージにするか」のコミット計画を日本語でユーザーに提案する。
   - 提案フォーマットの例:
     - コミット1（対象ファイル: `A.ts`, `B.ts`）
       - メッセージ: `#51 feat: ユーザー管理のためログイン機能を追加する`
     - コミット2（対象ファイル: `C.css`）
       - メッセージ: `#51 style: 視認性向上のためボタンの色を変更する`
8. ユーザーから構成の提案に対する承認（OKなど）を得た後にのみ、後続の操作（`git commit` コマンドの提示や実行など）を進めること。
